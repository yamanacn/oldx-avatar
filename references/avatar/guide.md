# 数字人阶段：让图片里的人开口说话

把"一张人物图片 + 一段配音"变成一条数字人视频。配音和文案由配音阶段产出，放在共用的项目目录里；这一阶段拼出 `avatar/final_avatar.mp4`，再跳剪成 `avatar/final_jumpcut.mp4`，后者就是本技能的最终交付，字幕、图形动画这类包装不在本技能范围内。

脚本路径相对本技能目录。项目目录（下文称 `workdir`）默认是最近一次的项目：

```
python scripts/voice/project.py latest        # 打印最近项目目录
```

需要的前置：`<workdir>/copy.txt`、`<workdir>/out/merged.wav`、`<workdir>/out/words.json`。缺任何一个，先回到配音阶段补上（用户自带录音的做法见 `references/pipeline.md`），不要自己估时间或另录配音。

每个脚本的全部参数、产出文件和退出码见 `references/tools.md`；加 `--json` 时最后一行是机读结果。

## 红线

- **密钥不回显**，只说来源；**不从聊天记录、日志里翻密钥**，没有就问用户。
- **不向用户索要应用 ID**：云端应用已内置（`DEFAULT_APP_ID`），别的账号的 Key 可直接调用，用户只需要给 RunningHub 的 Key。接口真的报“应用不存在／无权限”时，把原始报错原样转告用户，不要自己推断“需要你的应用 ID”。
- **不用 `ultra` 实例**：用户只授权过 `plus`。失败或显存不足时报告，由用户决定，不自行升级。
- **不改图片内容**：只允许按比例中心裁剪（并告诉用户裁了多少），不美化、不换背景。
- **不改文案**，提示词里的台词用原文。
- 提交（花钱）前用一句话告诉用户段数和预计费用（见下）；用户这次的请求里已经明确说了"开始跑"就直接提交，否则等一个确认。

## 流程

### 0. 先要图片，再查环境

1. **先向用户要人物图片**，第一件事，其他都不先问。图片决定画幅、尺寸和提示词，所以放在最前面。
2. 查环境：

   ```
   python scripts/avatar/check_setup.py
   ```

   - 退出码 3：没有 RunningHub Key。把脚本输出的引导文案**原样**发给用户并停下等待（要求用户获取后**直接粘贴到对话输入框**，其余由你处理）。**不要让用户打开终端、设置环境变量或运行任何命令**，所有命令都由你来执行。用户发来后**直接保存并告知**，不再追问：用 Write 工具写入 `~/.runninghub/api_key`（不要有多余内容），运行 `python scripts/avatar/check_setup.py --lock`，然后只说一句"已收到并保存在本机（仅你的账户可读），之后不用再发；想删除告诉我"，不复述 Key。
   - 退出码 5：还没记录会员档位。用中文问用户**一次**"你的 RunningHub 是哪一档会员"，把脚本输出的档位表列给他选，由你执行 `--set-plan`。并发数由档位决定（没记录只按 1 路）。
   - 其他情况继续。

### 1. 处理图片

```
python scripts/avatar/prepare_image.py --image <图片> --workdir <workdir> --mouth-box x0,y0,x1,y1
```

`--mouth-box` 是**你看图后给出的嘴的位置**（占画面宽高的比例，例如 `0.42,0.46,0.58,0.58`），成片质检用它定位嘴部；先看一遍图再写，不要瞎填。

- 在 16:9、9:16、1:1、3:4、4:3、21:9 里选最接近的一档，目标尺寸是该比例下约 100 万像素、边长取 32 的倍数（16:9 为 1376×768，9:16 为 768×1376，1:1 为 1024×1024，4:3 为 1184×896，3:4 为 896×1184，21:9 为 1568×672）。
- 比例不完全一致时做最大范围的中心裁剪，不拉伸。
- **先看 `risks`**：脚本查得出来的风险（偏糊、过暗过亮、透明背景、放大太多、嘴离上边太近、脸太小、人物不在中间）列在这里，有就告诉用户，让他换图或确认继续——生成出来救不回来。
- **必须看一眼 `avatar/image_crop_check.jpg`**（原图上画了裁剪框），按 `checklist` 逐项确认：头顶、手被裁到了就告诉用户，让他换图或自己先裁；没问题再继续。图片比目标小会被放大，要把脚本的提示转告用户。
- **同时看图片里的起始姿态**（每一段的开头都是这张图，结尾都要回到这个姿态）：最理想是嘴闭着、表情平静、头正、双手自然放在身前或桌面。嘴张开或双手抬在半空的图能用，但每个接缝都会跳一下（实测：嘴闭着的图接缝跳变 4.8–5.8，嘴张开的图 8.5–10.2）——告诉用户一句“这张图嘴是张开的／手抬在空中，接缝会比较明显，换成嘴闭着、手自然放着的图会更稳；也可以直接用这张”，由用户决定，不替他拒绝。用了就在下一步把图片类型标成“非中性”。
- **要展示商品的片子**（带货、产品介绍）：商品必须已经在图里——手里拿着，或摆在桌面、身旁。图里没有的东西提示词变不出来，硬写会凭空多出一个走样的物件。图里没有商品而文案又要展示时，告诉用户换一张带商品的图，或者接受“只说不展示”。

### 2. 分段

```
python scripts/avatar/plan_segments.py --workdir <workdir>
```

用 `python scripts/pipeline.py segments --workdir <workdir>`（就是 `plan_segments.py`）。只设"每段最长 14 秒"：全长不超过 14 秒就整段；否则在配音的**停顿**处断开，**切点优先句末（。！？），其次逗号处**，没有标点的停顿最后才用，同时尽量均分；多一段能让切点都在句末、逗号处时宁可多一段。停顿直接从 `merged.wav` 里检测；逐词时间和配音对不上（检测出的停顿超过 20% 落在词中间）会停下，按提示重新对齐。找不到合适停顿才依次放宽（句末标点、词边界）；放宽之后仍然优先用真正的停顿，没有停顿的标点处只在不得不用的地方用（语速快的播报类配音常遇到：一截超过 14 秒都没有 0.25 秒以上的停顿）。结果写入 `avatar/plan.json`，每段音频切成 `avatar/seg_NN.wav`。

### 3. 写提示词

先读 `references/avatar/prompt-rules.md`，按它的三步走：**看图判断图片类型 → 通读文案确定场景 → 逐段写动作**。然后照 `references/avatar/prompt_src.example.json` 写 `avatar/prompt_src.json`。每段提交给云端的提示词只有四块：

```
<固定镜头，无运镜>

双手的原姿态：……（一句）
身体的原姿态：……（一句）

动作：从<Picture 1>的姿态开始，……；最后……，回到<Picture 1>的姿态。
```

要点（细节、理由和实测依据都在 `prompt-rules.md`）：

1. **先判断图片类型，再写动作。** 用 Read 工具看 `avatar/image.png`，按景别归到五类之一：A 近景、B 半身无桌面、C 半身有桌面、D 站姿、E 全身远景；再看有没有附加条件：`持物左`／`持物右`、`旁物`、`非中性`（嘴张开、手抬在半空）。图片类型决定**能做**哪些动作。
2. **再按场景定幅度和取向**（`references/scenarios.md`）。
3. **每段的动作写成一整段中文连续叙述**：从首帧姿态写起，按先后顺序连 3–5 个动作，倒数第二个动作让头和上身回正，最后一句回到 `<Picture 1>` 的姿态。不写时间、不引用台词、不用引号。
4. **双手统一描述**：写“一只手……另一只手……”“双手……”，不分画面左侧、右侧。
5. **避开引出过多手或异物的写法**：双手交叉、叠放、往中间靠拢；手抬过肩；一只手在一句里去好几个位置；手已贴着画面边缘时往外的动作；“带”“拿”“托着”“抱”“捧”。
6. **底线不随图片和场景变**：不写嘴和表情（情绪只能写成动作）、不用比喻、只写左右和上下不写前后、只写图里有的东西、不写具体手指数、不碰脸和佩戴物。
7. **逐段读着写**，不要用按关键词套动作的脚本批量生成。

```
python scripts/avatar/build_prompts.py --workdir <workdir>
```

会拦的按提示改到通过；只给提示的（双手靠拢、手抬过高、叙述太长或太短）判断一下就行。输出的第一行会打印它认出的图片类型，核对一下。通过后提示词在 `avatar/prompts/`，**提交前打开一段看一眼**：第一行是固定镜头标签，没有画面描述和台词。

### 4. 预览，再提交

```
python scripts/avatar/run_avatar.py --workdir <workdir>          # 预览：不联网，不花钱
```

预览会列出尺寸、实例、工作流版本、档位对应的并发数和每段情况（种子、哪些段现有的片段会先收进历史）。然后按下面估算告诉用户预计费用：

- **预计费用**：`run_avatar.py` 的预览直接给出预计 RH 币（按本机以往各段的实际费用算，每秒配音约 8–12 币，中位 10 币；本机记录不够时按参考值 10 币/秒），报给用户时说“以 RunningHub 后台为准”。旧模型按人民币计费，实测约 0.044–0.054 元/秒配音。

预览还会写出这一版配音用户确认过没有（`voice_approved`）。**提交前停下等用户回复**：把段数和预计费用告诉用户；配音还没确认的，把 `out/merged.wav` 一起发给他试听。用户回复确认后提交：

```
python scripts/avatar/run_avatar.py --workdir <workdir> --voice-approved "用户回复的原话" --yes
```

- **配音试听的确认写在代码里**：`--yes` 不带 `--voice-approved` 会以退出码 5（need_user）拒绝，不提交、不花钱。只能填用户在对话里回复的原话（例如“配音可以，开始吧”）；用户开头就说过“配音不用听、直接做”的，填那句话。**用户还没回复时不能自己编一句**。这句话和当时 `out/merged.wav` 的指纹记进 `<workdir>/voice_review.json`：配音没变时，之后重跑某几段不用再给；配音重新合成过（换语气、改文案……），旧的确认自动作废，要请用户再听一次。

- 并发数 = min(段数, 会员档位并发数)，多出来的段在本地排队。
- **重试按层分开，避免重复计费**：
  - 上传、下载各自重试 3 次；云端已成功时下载失败**只重下，不重新提交**。
  - 提交被并发/排队/限流拒绝，等 20 秒再提交，最多 12 次。
  - 任务失败先判断类型：余额不足、参数或权限错误直接停下报告（重试没用）；其余（含显存不足）退避后重提交一次（失败任务不计费），仍失败就报告原因，**不要自行换 `ultra`**。
  - 轮询超时不会重新提交：任务号保留在 `result.json` 的 `pending` 里。
- **断点续跑**：任务号一提交就落盘。脚本被中断、超时或部分段失败后，直接重跑同一条命令：已成功的段沿用，仍在云端的任务会被续上，只补真正失败的。想强制重做某段才用 `--only <段号>`，全部重做用 `--all`。
- **旧片段不会丢**：重做某段之前，它现在的片段会自动收进 `avatar/takes/seg_NN/`，连同当时的种子、工作流版本和提示词全文。不要自己复制或删除 `clips/`。`--note "一句话"` 可以给这次生成的版本记个备注（例如改了什么写法），之后对比时有用。
- **工作流版本**：每段都记下提交时的工作流版本。**用户说改过云端工作流时，先记一个版本标签再提交**：`python scripts/avatar/check_setup.py --set-workflow "日期 改了什么"`。同样的提示词和种子，换一版工作流结果就可能不同；预览会提示哪些沿用的段是别的工作流版本生成的。
- **随机种子**：预览里每段都会列出要用的种子。不带 `--seed` 时：没跑过的段用默认值 42；跑过的段沿用上次的种子，**但提示词和工作流都没改时自动换成随机种子**（同样的输入加同样的种子会得到一模一样的结果，重跑等于白花钱）；改了提示词就沿用种子，方便看清是不是提示词起了作用。`--seed random` 给每段各取一个随机数，`--seed <整数>` 指定。种子随任务一起记在 `result.json` 里。
- **排队和取消**：并发名额被占满时脚本会自动排队重试（默认最多等 30 分钟，`--queue-min` 改）；要停掉还在云端跑的任务用 `run_avatar.py --cancel`（`--only` 只取消某几段；取消接口没实测过，失败就请用户到 RunningHub 后台手动取消）。
- 退出码 4 是密钥被拒绝：让用户重新获取。
- 改过重试逻辑后用 `python tests/avatar/test_retry.py` 重跑模拟测试（不联网，10 种情况）；改过历史版本或工作流记录的逻辑后跑 `python tests/avatar/test_takes.py`。

### 5. 拼接与质检

```
python scripts/avatar/finalize.py --workdir <workdir>
```

每段按音频时长裁掉模型补的多余帧再拼接；**声音直接用项目里的原配音**，不用云端回传的音轨。质检项：分辨率、时长与配音差、黑帧和冻结候选。

**每段开头的几帧也裁掉**（用户看对比片后定的）：云端片段开头的 2–4 帧几乎不动，接在上一段后面会顿一下。从第 2 段起每段开头裁掉 4 帧，**同时裁掉配音里同样长的一段开头静音**——分段切在停顿的中点，每段开头本来就是静音，所以口型不会错位；最多裁到这一段第一个字之前 0.08 秒，不剪到字头。同一份素材对比：接缝后画面不动的帧平均从 2.1 帧降到 0.2 帧，全片短约 2 秒。`--head-frames 0` 不裁。

所以成片 `final_avatar.mp4` 比配音 `merged.wav` 略短。各段在成片上的起止写在 `avatar/finalize.json`，逐词时间换算到成片时间轴上写在 `avatar/words_final.json`；质检、跳剪、字幕都按成片的时间走，不用自己换算。

再做内容质检：

```
python scripts/avatar/qa_video.py --workdir <workdir>
```

它输出几类提示、几张图和一份异常时间段清单 `avatar/anomalies.json`（都是粗略指标，用来**发现该看的地方**）：

- **镜头**：每段和它自己的第一帧比，整幅画面的缩放偏离 1 超过 6%、持续 1 秒以上，就标为“镜头被推近／拉远”。人物在动不影响这一项；人物占满画面、背景很少时可能判断不了，会说明。这一项可靠，标出来就是真有推拉。
- **接缝**：逐帧顺序解码，量每个接缝前后的跳变，超过全片相邻帧差中位数 3 倍才标出；同时生成 `avatar/seams.png`（每行一个接缝，切点前后各两帧），**用 Read 工具看一眼**有没有变脸、变构图。

- **逐秒色彩**：每一秒的背景色和输入图片比，色相偏转超过 20° 或彩度降到图片的 55% 以下就记为异常时间段（实测：正常波动色相 ≤12°、彩度 0.9–1.7 倍；变青、变黄绿时色相偏转 26° 以上；褪成灰白时彩度 ≤40%）。同一色调下变亮、变浓不算异常。

- **嘴逐秒图 `avatar/mouth_strip.png`**：每秒一格，红 S 表示这一秒音频在说话。**必须用 Read 工具看**：说话的秒里嘴一直闭着就是问题段。帧间差分会被头部晃动干扰，漏检过，所以最终以这张图为准。
- **两只手**：每段里近似静止的帧占比，任一只手超过 60% 才标出。这只是参考：模型不会和写的一模一样，手偶尔停一下、某个动作没做出来都可以接受。
- **色彩**：某段背景色与各段中位色的色差 >25 才标出，也就是整段明显变成另一种色调的情况。

- **全片总览图 `avatar/sheets/overview_NN.jpg`**：每 0.5 秒一格，每格宽 200 像素，每张 10 列 × 6 行 = 30 秒。**必须用 Read 工具逐张看**：多手（手叠成几层、凭空多一只）、手里多出东西、烧上字幕、手形错乱、商品变样，这几类脚本都判断不了（试过按肤色面积找多手，分不开），只能靠看这几张图。看到可疑的格子，用 `contact_sheet.py --times` 在那几秒放大再看：

```
python scripts/avatar/contact_sheet.py --video <workdir>/avatar/final_avatar.mp4 --times 12.0,12.5,13.0 --width 240 --out <workdir>/avatar/zoom.jpg
```

**发现问题段怎么补救**：每段用的随机种子记在 `result.json` 里，**同样的输入加同样的种子，重跑会得到同样的结果**。所以重跑时至少要换一样：

- **先换种子**：`run_avatar.py --workdir <workdir> --only <段号> --seed random --yes`。提示词不用改，最省事；多手、手形别扭、偶发的多出东西这类“这次没画好”的问题先试这个。
- **换种子后同一处还是出问题，再改提示词**：说明是写法引出来的，按下面的办法改那一段的动作编排，再用 `--only <段号>` 重跑（不带 `--seed` 会沿用这一段上次的种子，方便看清是不是提示词起了作用）。

按问题类型改提示词的办法（写法上的禁忌见 `prompt-rules.md` 第四节“引出过多手或异物的写法”）：

- **多手、手里多出东西**：先看这一拍写的是不是双手交叉、往中间靠拢、举过肩、一句里去好几个位置，或者用了“带”“拿”“托着”这类字；是就改掉，否则先换种子。
- **镜头被推近／拉远**：先问用户云端工作流最近有没有改过——这类问题和工作流版本、这一段的种子关系更大，和动作写法关系不大；确认提示词第一行有固定镜头标签，再换种子重跑这一段。

- **说话时嘴一直闭着或几乎不动**：改那一段的动作叙述（换几处动作的写法或先后）再用 `--only <段号>` 重跑，并用嘴部逐秒图确认。
- **一只手整段整段不动**：把那一段里这只手的动作改成看得见位移的（落到某处、托着、在落点上轻点），让它当几次主手，再用 `--only <段号>` 重跑。偶尔停一下不用管。
- **色彩偏移**：改提示词有效。

**同一段跑过几次后，挑最好的一版用**：每次重跑的旧片段都在历史里，不必为了挑选再花钱。

```
python scripts/avatar/takes.py --workdir <workdir>              # 每段现在用的是哪一版、还有哪些历史版本
python scripts/avatar/takes.py --workdir <workdir> --use 6=2    # 第 6 段换成历史版本 2
python scripts/avatar/takes.py --workdir <workdir> --show 6=2   # 看那一版当时的提示词
```

换完重新跑 `finalize.py`、`qa_video.py`，请用户再看一次新的 `final_avatar.mp4`，确认后再跑 `jumpcut.py`。列表里会标出两类要留意的：现在的提示词和生成那段时已经不一样；成片里混用了不同工作流版本生成的片段。

**用户说了这条视频还要做后期包装的话，先考虑遮盖。** 人物视频是本技能的最终产物，默认按上面的办法改输入重跑。但重跑要花钱，所以如果用户明确说之后还要加字幕、图形、画中画，`anomalies.json` 里的异常可以留给后期盖掉（那几秒把人物缩小或移开、用内容盖过去），不必重跑——把清单和时间点在交付时告诉用户。即使这样，异常在片头 3 秒内、或异常总时长超过全片约 40% 时仍然重跑。

**哪些不用补救**（用户看片后定的标准）：段与段之间颜色有小幅跳变、灯光颜色有自然的变化、手偶尔停一下，都属于可以接受——切点都在说话的停顿处，正常剪辑也会有这种跳变。这些情况在交付时提一句即可，不要为它重跑。只有嘴不动、整段变成另一种色调、画面里多出明显不该有的东西、手形或人物明显出错时才补救。

每段最多补救 2 次，仍不行就如实报告。

### 6. 跳剪

质检没问题后，把说话之间的停顿剪掉，节奏更紧。真人口播也是这样剪的，用户看片后认可，作为固定的最后一步。

**前提：先停下来，请用户确认人物视频没问题。** 质检做完就结束这一轮回复：把 `final_avatar.mp4` 的路径、时长和质检结果给用户，问视频有没有问题、能不能开始跳剪，然后**等用户回复，不要在同一轮里接着跳剪**。用户说要改哪一段，就先按第 5 步改好、重新拼接质检，再来问。用户回复确认后：

```
python scripts/avatar/jumpcut.py --workdir <workdir>                                        # 预览：会剪几处、剪成多长，不出文件
python scripts/avatar/jumpcut.py --workdir <workdir> --user-approved "用户回复的原话" --yes   # 用户确认后才执行
```

这一步的确认写在代码里：`--yes` 不带 `--user-approved` 会以退出码 5（need_user）拒绝，什么都不剪。`--user-approved` 只能填用户在对话里回复的原话（例如“没问题，开始跳剪”）；用户一开始就说过“不用给我看、直接剪”，填那句话。**用户还没回复时不能自己编一句填进去**——这句话会记进 `avatar/review.json` 和 `jumpcut.json`，交付时要原样引用。`final_avatar.mp4` 之后又重新拼过（换了历史版本、重跑了某段），旧的确认自动作废，要请用户再看一次。

- 0.3 秒以上的停顿剪掉，前后各留 0.08 秒，句子不显得赶；短于 0.3 秒的不动，那是句子里自然的气口。开头、结尾的静音也剪。
- 停顿中间夹着一下不到 0.1 秒的声音（气声、咔哒）也算同一个停顿，一起剪掉；不这样的话停顿被劈成两半，后一半不够长就漏剪，成片里会留下一个明显的小停顿。合并时至少一边是 0.25 秒以上的真停顿，几处很短的静音连在一起不算，免得剪掉说话中间的音。
- 声音和画面在同一时刻、在帧边界上切，口型不会错位；接口处的声音做 8 毫秒淡入淡出，防止爆音。脚本自己核对画面时长和音画同步，没过就以退出码 1 停下。
- 剪辑点前后画面会跳一下，主要是手的位置变了。这是跳剪的正常现象（真人口播也这样剪），**不补救、不为它重跑**。前后帧差超过全片中位数 3 倍的剪辑点会列在结果里，最明显的 3 处拼成前后对比图 `avatar/jumpcut_points.jpg`，用 Read 工具看一眼，交付时把这几个时间点告诉用户。
- 原片 `final_avatar.mp4` 不动：它的时间轴和 `avatar/words_final.json`、`anomalies.json` 对应，后期包装仍用它。剪后和剪前的时间对应在 `avatar/jumpcut.json` 的 `map` 里。

不在项目里的视频（比如别处做好的口播）也能剪：`python scripts/avatar/jumpcut.py --video <视频> --out <输出.mp4> --yes`，同样先问用户视频有没有问题。输出文件被播放器占着时，新的另存为 `*_新.mp4`，退出码 6，关掉播放器重跑即可。

### 7. 底部字幕（附加功能，用户说要才做）

**先问用户要不要字幕**，开头没问过的在第 6 步请用户确认视频时一起问；用户没说要就跳过这一步。用户要的话：

```
python scripts/avatar/captions.py --workdir <workdir>         # 预览：每条字幕的文字和时间、放在画面多高，不出文件
python scripts/avatar/captions.py --workdir <workdir> --yes   # 烧进 avatar/final_jumpcut.mp4 → avatar/final_subtitled.mp4
```

规则（用户看样片后定的）：

- **文字是原文案，一个字不改。** 句中的逗号、顿号、问号、感叹号保留，句末的句号去掉；中文和英文、数字之间留一个空格（“用 AI 把 Adobe 的七个软件”）。
- **一句一条，一屏一行**，竖屏每条最多约 12 个字宽。长句先在逗号处断，没有逗号再在词与词之间断：词边界用中文分词，识别结果认为是同一个词的地方也不断（分词会把“隔空投送”切错）；不断在英文、数字中间，尽量不让一条以“的、了、着”开头，也尽量不留一两个字的短条。**不跨句合并**——把上一句的结尾和下一句的开头拼成一条，读着像说错了。
- **专有名词不拆开**：分词会把“英伟达”“国星宇航”切成“对英/伟达”“国星/宇航”。常见公司名和文案里重复出现的三四字词自动保护；只出现一次的公司名、产品名、人名，预览时看到被拆开了，就用 `--terms 国星宇航,星算` 列出来再跑。
- **时间**：原文逐字对到逐词时间 `out/words.json` 上（识别有同音错字，所以是对齐，不是查找），再按 `avatar/jumpcut.json` 的 `map` 换算到跳剪后的时间。每条显示到下一条开始。
- **样式**：粗黑体（Windows 用微软雅黑），字号约为画面宽度的 6.5%（768 宽约 50px，1080 宽约 70px），白字黑描边加轻微阴影，不加底板，水平居中。
- **位置**：整行字幕落在画面 68%–80% 高度里，脚本按全片的画面变化挑手最少经过的位置；下面约 20% 留给平台的标题和按钮。口播人物的手常在胸前活动，字幕和手偶尔重叠是正常的，有描边读得清。
- **自检**：字幕拼起来和文案逐字一致、每条不超过一行、不重叠、不超出视频，没过就不烧录（退出码 1）。另出一张抽帧图 `avatar/subtitles_check.jpg`，**用 Read 工具看**：字幕有没有压到脸、有没有出画面。
- 同时导出 `avatar/subtitles.srt` 和 `.ass`，用户可以拿去剪映里改字、改样式。字号、位置不合适时用 `--font-ratio`、`--position` 调。
- 人物视频改过、重新跳剪之后，字幕也要重跑（脚本发现 `final_avatar.mp4` 比跳剪版新会停下）。

**别的语言的字幕**（例如英文配音配中文字幕）：用户要了才做。译文由你按原文写，存成 `avatar/translation_<语言>.json`：

```json
{"units": [{"src": "原文的一句或一个分句", "text": "这一句的译文"}, ...]}
```

`src` 按顺序拼起来必须等于 `copy.txt`（脚本会核对），长句按分句拆成几项，时间更准。然后 `captions.py --workdir <workdir> --translation avatar/translation_zh.json` 预览、加 `--yes` 烧录。每个 `src` 在配音里的起止由原文对逐词时间得到，译文按上面的中文规则断成一行一条、按各条宽度分这一句的时间。预览里看断行：专有名词被拆开（“大型/银行”）就用 `--terms` 保护，或者把这一句的译文换个说法；原文案仍然一个字不改。交付时说明译文是你写的，请用户核对。

不在项目里的视频也能加：`python scripts/avatar/captions.py --video <视频> --copy <文案.txt> --words <words.json 或 plan.json> [--jumpcut <剪辑记录.json>] --out <输出.mp4> --yes`。

### 8. 清理，然后交付

交付前清掉随时能免费重新生成的文件（质检和检查图、旧的配音版本、包装的静帧和样段），给磁盘减负：

```
python scripts/cleanup.py --workdir <workdir>          # 预览：能清什么、多大
python scripts/cleanup.py --workdir <workdir> --yes    # 删第 1 类
```

成片、当前片段、配音、逐词时间、提示词都不会删。预览里第 2 类（配音缓存 `--cache`、人物视频历史版本 `--takes`）和第 3 类（手工留的实验目录，`--archive 名字`）删了要再花钱或找不回来：只在交付时报一句大小，用户说要清再删，不自己删。用户说“磁盘满了”“清一清”时，用 `cleanup.py --all` 看所有项目能腾出多少。

先给结论，再给依据，用中文：

- 一句话结论：成片（`final_jumpcut.mp4`）路径、尺寸、时长、几段、费用。
- 跳剪：从多长剪到多长、几个剪辑点、画面跳得明显的时间点。
- 字幕（加了才写）：`final_subtitled.mp4` 和 `subtitles.srt` 的路径、几条、放在画面多高、停留特别短的几条。
- 分段情况：每段时长和断在哪（停顿还是别的）。
- 质检结果：脚本的几项、接缝图、嘴逐秒图和抽帧的观察，每个问题给出时间点。
- **没验证的**如实写：口型是否对准、手势细节、人物是否前后一致——脚本和静帧都判断不了，请用户播放确认。
- 清理：腾出了多少；第 2、3 类还有多少可以清（用户说要再删）。
- 提醒：Key 如果在聊天里出现过，建议重新生成。
- 还要加字幕、图形动画的话，说一句可以交给 oldx-oneshot 的包装阶段或 visual-broll-director，项目目录直接通用。

产物都在 `<workdir>/avatar/`：`final_jumpcut.mp4`（成片）、`final_avatar.mp4`（没剪停顿的，后期包装用）、`jumpcut.json`、`jumpcut_points.jpg`、`final_subtitled.mp4` 和 `subtitles.srt`（加了字幕才有）、`plan.json`、`prompts/`、`clips/`（各段现在用的原始视频）、`takes/`（各段的历史版本）、`result.json`（任务号、种子、工作流版本、费用）、`qa.json`、`qc_frames.json`、`anomalies.json`、`sheets/`（总览图）。

## 失败时怎么办

| 现象 | 做法 |
|---|---|
| 缺 `words.json` / `merged.wav` | 先回到配音阶段 |
| 某段云端失败（如显存不足） | 脚本已自动重试一次；仍失败就报告原始错误。告诉用户，建议把上限调小（`plan_segments.py --max 10`，需要重新写提示词），或由用户决定升级实例 |
| 脚本中途被打断 / 超时 | 直接重跑同一条命令，会续上已提交的任务，不会重复计费 |
| 提交被拒（并发/排队） | 脚本会等待重试；仍不行就确认会员档位是否记录对了 |
| 密钥被拒 | 让用户重新获取并发给你 |
| 接缝有跳变 | 看 `seams.png`，指出是哪个接缝；通常是该段首尾姿态没回到原位，改那一段的动作叙述（倒数第二个动作就回正）后用 `--only` 重跑。图里嘴张开、手抬在半空时接缝本来就会跳一些，提示词只能改善一部分 |
| 同样的提示词和种子，这次和上次结果明显不同 | 多半是云端工作流改过：问用户，记一个工作流版本（`check_setup.py --set-workflow`），再看 `takes.py` 列表里各段分别是哪一版工作流生成的 |

接口、已验证数据和没验证的事项，见 `references/avatar/runninghub-notes.md`。
