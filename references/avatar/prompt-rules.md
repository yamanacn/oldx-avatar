# 提示词编排规则

写 `avatar/prompt_src.json` 之前读。目标：让每一段的动作“从这段话里长出来”——手有事做、有起有落，头和身体跟着动，并且不碰嘴。

按三步走，顺序不能反：

1. **看图，判断图片类型**——决定这张图**能做**哪些动作（第二节）。
2. **通读文案，确定场景**——决定从能做的里面**选**哪些、做多大（第三节）。
3. **逐段写动作**——每段写成一整段中文连续叙述，从首帧状态讲到回到首帧（第四节）。

第一节的底线对所有图片、所有场景都一样，先记住。

各条规则后面标了依据：**已验证**是实际生成过、量过或用户看片确认过的；**未验证**是按模型已知的毛病推出来的，用到时在交付里说明，并留意成片。

## 一、所有图片通用的底线

这些会被 `build_prompts.py` 拦下，改到通过为止。

- **不写任何与嘴部有关的描述。** 微笑、笑意、嘴唇、口型、换气、表情、神态、“露出……的笑”、情绪形容词（亲切、惊喜、无奈、热情……）一律不写——画面描述、双手描述、动作叙述都不写。嘴怎么动由云端应用和音频负责。早期版本在动作里反复写“嘴唇自然闭合”、在开头写“带着笑意”，结果有一段约 10 秒说话时嘴始终闭着。所以**情绪只能写成动作**：文案在吐槽，就写“手掌在桌面上轻拍一下”，不写“生气地”。
- **不用比喻。** 不写“像拿着话筒”“像端着杯子”“像捧起一摞东西”——模型会把比喻里的东西画出来（实测：写了“像捧起所有东西”，手上真的多了一团东西，重跑一次还在）。直接写手怎么动：“握拳抬到胸前”“掌心向上并拢向上一托”。
- **只写左右和上下，不写前后。** 不写前倾、后仰、后靠、探身，手不写“向前推出”“伸向镜头”“指向镜头”——人一朝镜头靠近或远离，模型就把它做成推近拉远，背景里的字和物件会糊成重影（实测：写了“上身微微前倾”，那几秒背景的字牌变成了两层）。需要“推近强调”留给后期做。
- **只写图里有的东西。** 商品、道具、桌面，图里有才能拿、碰、落上去；图里没有的写了就会凭空多出一个走样的物件。
- **不写具体手指数**（“伸出三根手指”“比个三”会出错，改用手掌或食指示意）。描述手形的“五指张开”“手指并拢”可以写。
- **不触碰脸、头发和佩戴物**（眼镜、耳饰、发夹、手表、麦克风）；手不高过下巴、不挡脸。
- **不写镜头运动、转身、站起、走动；视线不离开镜头。**
- **不引用台词，不用引号，不写时间点。** 提示词里放过台词原文时，出现过整段烧上字幕（还是错字）；引号里的字可能被当成画面上的文字；时间段可能被当成切镜头。
- **身体和手的动作不用「带」「拿」「托着」「抱」「捧」。** “身体向画面右侧轻轻一带”之后胸口多出一团布状物，只把这几个字换成“上身向画面右侧轻轻侧倾一下”、其余不动重跑，就没有了（2026-10-14，已验证一次）。
- **每段从图里的姿态开始，最后回到图里的姿态。** 每一段的开头都是这张图，段与段才能接上。

## 二、看图：判断图片类型

先用 Read 工具看 `avatar/image.png`，回答下面的问题，把结论写进 `prompt_src.json` 的 `image_type`。没填这一项校验不通过。

### 先读出这些

- **手可以落在哪**：桌面、腿上、腰侧、身前交握，还是只能落到画面下沿以外。
- **手边有什么能碰的**：桌面、扶手、手里拿着的东西、摆在旁边的商品。
- **手的活动范围多大**：往上到哪、往两边到哪会出画面。
  **手已经贴着画面边缘的图，不写向外的动作**：不写向两侧展开、摊开、向外甩，也不让手落出画面，所有手势都在身前、往下做。手没有往外的空间时，模型会把镜头拉远来容纳动作，手里还可能多出东西（已验证）。这类问题要靠看总览图发现。
- **头和身体能动多大**：头顶和两侧留了多少空间。
- **两只手的原姿态**：各在什么位置、掌心朝向、手指状态。“画面左侧／右侧”一律按观众看画面的方向，避免和人物的左右手混淆。只写看得见的，不猜。

### 五种类型：按景别分

景别决定哪一层能出动感，所以用它做主分类。

| 类型 | 怎么认 | 主要靠哪层 | 手的落点 | 依据 |
|---|---|---|---|---|
| **A 近景** | 胸口以上，手不在画面里或只露一点 | 头为主，肩为辅 | 没有 | 未验证 |
| **B 半身无桌面** | 腰或胸以上，双手在画面里，身前没有台面 | 手、头、身体三层都用 | 画面下方（出画）、身前交握 | 已验证（三次生成） |
| **C 半身有桌面** | 坐在桌前，桌面在画面里 | 手为主 | 桌面 | 已验证（技能原有的实测多是这类图） |
| **D 站姿** | 站着，七分身或更大 | 身体为主 | 腰侧、身前交握、身体两侧 | 未验证 |
| **E 全身远景** | 人只占画面一小部分 | 手臂的大动作和重心 | 同 D | 未验证 |

**A 近景**

- 不写手势。手从画外伸进来容易变形；`hands` 写“双手不在画面里”即可。
- 每个动作都配一个头的动作，隔一个配一次肩（耸肩、单侧肩膀一抬、肩膀一沉）。
- 脸占画面大，头的幅度要小：偏、侧倾都以“一点”为限，不写“明显”。

**B 半身无桌面**

- 三层都写。手没有看得见的落点，“歇一拍”只能写落到画面下方，或收到身前交握。
- 有落点的动作换成不需要台面的：双手一拍、拳头敲掌心、手掌向下一压。
- 身体可以做明显的侧倾和重心移动，这类图的动感一半靠它。

**C 半身有桌面**

- 手为主，有落点的动作最多：轻拍桌面、食指在桌面点两下、手落到桌面歇一拍再抬起。
- 上身只做小幅侧倾和耸肩。桌沿是参照物，上身一晃就显眼，不写“明显”的身体动作。

**D 站姿**

- 身体为主：重心从一侧移到另一侧、上身侧倾、单侧肩膀一抬。
- 手歇着时落到腰侧（叉腰）、身前交握，或自然垂到身体两侧。
- 不写腿和脚，不写走动、转身、迈步。

**E 全身远景**

- 写手臂的大动作（抬起、展开、指向一侧）和重心移动。
- 手指、头的细动作画不出来，不写“食指点一下”“头一偏”。
- 嘴在画面里很小，口型容易糊，质检时专门看嘴逐秒图。

### 三个附加条件：和景别无关，认出来就叠加

**持物——一只手里拿着东西**（写 `持物左` 或 `持物右`，指画面哪一侧的手）。已验证。

- 这只手只做四件事：抬高一点、转动手里的东西、轻点一下、落到胸口高度再抬回。幅度小，东西始终在画面里、不挡脸。
- 另一只手承担全部主要手势；“两只手轮流当主手”对这类图不适用。
- 段首段尾东西回到图里的位置，否则接缝会跳。
- 不写打开、撕开、挤出、倒出、涂抹这类会让东西变样或多出新东西的动作。

**旁物——东西摆在桌面或身旁**（写 `旁物`）。未验证。

- 优先写“手掌摊开指向它”“手落在它旁边”“食指在它旁边的桌面上点一下”。
- 拿起来再放回去也能写，但出错的机会多（放回的位置对不上、东西变样），一条片子里少用，抽帧时专门看。

**非中性——图里嘴张开、手抬在半空或头偏着**（写 `非中性`）。已验证。

- 每一段的第一帧都是这张图。上一段结尾在停顿里嘴是闭的，下一段一开头嘴就是张的，每个接缝都会跳一下（实测：嘴闭着的图接缝跳变 4.8–5.8，嘴张开的图 8.5–10.2）。
- 结尾的回正要写完整：倒数第二个动作就让头和上身回正，最后一句只写回到原姿态（见第四节）。
- 告诉用户一句这张图的限制和更合适的图是什么样（嘴闭着、表情平静、手自然放着），由用户决定，不替他拒绝。

### 写进 prompt_src.json

```
"image_type": "B+持物右+非中性"
```

类型字母在前，附加条件用 `+` 连接，没有就只写字母。校验脚本按它放宽或收紧：A 类不查手；持物的那只手不要求当主手；非中性时回正时间的要求更长；B、D、E 类会提醒安排明显的身体动作。

## 三、通读文案：确定场景

通读项目目录里的 `copy.txt`，弄清结构和每一处的语气——哪里在平静地讲，哪里在强调，哪里在吐槽、感叹、发问。配音阶段留下的 `emotions.json` 也是线索。

场景只管“选哪些、做多大”，不管“能不能做”——能不能做已经由图片类型定了。各场景的语气见 `references/scenarios.md`。

| 场景 | 幅度 | 取向 |
|---|---|---|
| 知识口播、测评、教程 | 中 | 比量、指向、列举 |
| 直播带货、商品口播 | 大 | 有落点的动作多：报价、强调卖点、催单、展示商品 |
| 产品介绍、品牌宣传 | 小到中 | 托起、展示、指向；少用拍、敲 |
| 课程、培训、通知 | 小 | 步骤、列举；信息密处少动 |

### 动作跟着这句话的性质选

按图里有什么来换，只从图片类型允许的里面选。

| 这句话是 | 手 | 头和身体 |
|---|---|---|
| 平静叙述、停顿 | 手落到落点歇一拍，再抬起 | 重心慢慢从一侧移到另一侧，肩膀放松 |
| 强调、下结论 | 有落点的动作：轻拍、双手一拍、拳头敲掌心、手掌向下一压 | 头随重音一顿，或肩膀一沉再放松 |
| 吐槽、无奈 | 摊手、甩一下手 | 耸一下肩，头向一侧一偏 |
| 疑问 | 掌心向上摊开 | 头侧倾，同侧肩膀略抬 |
| 兴奋、得意 | 握拳小振一下、单手叉腰 | 上身向上一挺，上身左右轻晃 |
| 数量、对比、步骤 | 两手比宽窄、比高低；一只手当台面，另一只在上面点 | 上身随每一项轻点一下 |
| “我”“这个”“那边” | 指自己、指画面一侧或下方 | 头随手的方向转一点再回正 |
| 列举、信息密集 | 一只手随每一项轻点，另一只托着 | 少动 |
| 打招呼、收尾 | 挥手、掌心向上在身前托起 | 点头 |

### 带货特有的

| 这句话是 | 动作 |
|---|---|
| 报价格、报优惠 | 落在数字上的一下：手掌轻拍桌面、双手一拍、手掌竖起向下一切 |
| 划线价和到手价的对比 | 一只手抬到胸前比高的，另一只手在腰的高度比低的 |
| 强调卖点 | 一项一个落点：食指在另一只手掌上点一下、握拳小振一下 |
| 讲痛点 | 双手向两侧摊开，肩膀一耸再放下 |
| 催下单、数量有限 | 快而小的重复：一只手连续向下轻点两下、双手一拍 |
| “点下方链接” | 食指指向画面下方或左下方，停一拍再收回 |

指向只在画面平面里指——下方、两侧、斜下方；不指向镜头。

## 四、写动作：一整段中文连续叙述（默认写法）

这是 2026-10 比较了六种写法之后定下来的写法，用户看片认可。每段提交给云端的提示词长这样：

```
<固定镜头，无运镜>

双手的原姿态：双手抬在胸前两侧，掌心朝外。
身体的原姿态：上身坐直。

动作：从<Picture 1>的姿态开始，双手抬在胸前两侧；她握拳向上小幅一振，头跟着点一下；接着双手放低到胸口，上身向画面右侧轻轻侧倾一下；然后一只手跟着节奏向下轻点几下，头跟着点，随后头和上身回到端正；最后双手回到胸前两侧，回到<Picture 1>的姿态。
```

第一行和三个小标题由 `build_prompts.py` 拼好，你只写 `hands`、`posture` 和每段的动作叙述。`prompt_src.json` 的写法见第五节。下面四个开关不写就是这样：`motion_style` 中文连续叙述、`prompt_prefix` 固定镜头那一行、`include_scene` 不放画面描述、`include_line` 不放台词。

### 为什么是这样（依据）

| 做法 | 依据 |
|---|---|
| 第一行 `<固定镜头，无运镜>`，不放画面描述 | 同样的图、配音、种子和工作流下，换了三种动作写法，被拉远的总是同样几段；加上这一行、去掉画面描述之后，全部正常。这两处是一起改的，分不开是哪一处起作用，也只验证了一轮 |
| 动作写成一整段连续叙述，不分节拍、不写时间 | MiniMax H3 官方提示词写法对首尾帧模式的要求：首帧状态 → 中间变化 → 差异逐步收窄 → 末帧状态。和简化的节拍列表比，手的动作多约四分之一 |
| 用中文，不用英文 | 中文和英文的动作量、接缝几乎一样；用户定用中文 |
| 不放台词 | 放台词时出现过整段烧字幕；去掉之后再没出现 |
| 双手统一写成“一只手……另一只手……”“双手……”，不分画面左侧、右侧 | 分左右写时多手更多；统一写之后明显减少（同时还改了分段，分不开） |
| `hands`、`posture` 各一句短话 | 人物的样子由图片决定，提示词里写多写少看不出差别；短了不容易被误读 |

### 怎么写

1. **第一句从首帧写起**：“从<Picture 1>的姿态开始，双手抬在胸前两侧；”——照图里的姿态写。
2. **中间按先后顺序把 3–5 个动作连起来**，用“接着”“然后”“随后”衔接，分号隔开，读起来是一个连续的镜头。每个动作想清楚手、头、身体哪几层在动：
   - **手**：一只手做主要的事，另一只手需要时再交代一句（“另一只手放低到胸口”）。常用、没出过问题的动作：向下一压、向下一切、向下一按、轻点几下、握拳小幅一振、左右摆两下、放低到胸口、抬到肩膀的高度。
   - **头**：以左右为主——向画面一侧轻轻一偏、侧倾、轻轻摇头；点头只放在重音上，写多了也看不出来。
   - **身体**：写方向——上身向画面左侧侧倾再慢慢回正、肩膀微微一耸、肩膀一沉再放松、重心移向画面右侧。每段安排一两处“明显”的，其余用小的。
   - 动作跟着这一段话的语气选，取向见第三节的两张表。
3. **倒数第二个动作就让头和上身回到端正，最后一句只写回到首帧**：“最后双手回到胸前两侧，回到<Picture 1>的姿态。”实测结尾回正写得太晚，上一段还偏着头、下一段第一帧已是正脸，接缝会跳。
4. **长度**：一段 14 秒以内，动作叙述约 70–130 个字。太长动作挤在一起，太短后半段没动作；脚本会提示。

### 引出过多手或异物的写法，不要写

- **双手交叉、叠放、合十、往中间靠拢、收拢**：多手最常见的来源，写成“中间留出空隙”也没用。
- **手抬得过高**：“向上抬高”“举过头”会让举起的手叠成两层；写到“肩膀的高度”为止。
- **一只手在一句里去好几个位置**：“从左到右依次切”“双手交替点”会画出好几只手；要重复就写“在原处轻点几下”。
- **手贴着画面边缘时往外的动作**：图里手已经靠着画面两边，就不写向两侧展开、摊开、向外甩，也不让手落出画面（实测会把镜头拉远，手里还多出布状物）。
- **“带”“拿”“托着”“抱”“捧”**：见第一节。

### 旧写法已经删掉

以前的**节拍列表**（每行“起–止「关键词」：动作”）和**英文连续叙述**两种写法，2026-10-14 起不再支持：节拍列表里的「」关键词和时间段是烧字幕、镜头拉远的嫌疑；英文和中文效果一样，用户定用中文。旧项目的 `prompt_src.json` 是这两种写法时，`build_prompts.py` 会报错，把 `motions` 改写成中文叙述再跑。

## 五、prompt_src.json 的写法

照 `references/avatar/prompt_src.example.json` 写。默认写法只要填这几项：

```json
{"image_type": "B+非中性",
 "hands": "双手抬在胸前两侧，掌心朝外。",
 "posture": "上身坐直。",
 "lines": ["第1段台词原文", "……"],
 "motions": ["从<Picture 1>的姿态开始，……；最后……，回到<Picture 1>的姿态。", "……"]}
```

- `image_type`：第二节的图片类型，必填。
- `lines[i]`：**仍要填**每段的原文（取自 `copy.txt`，用 `plan.json` 每段的首尾词定位），脚本拿它和识别文字比对，防止段落错位，默认不会发给云端。
- 不用写的开关（默认值就是推荐写法，只有要改时才写）：`prompt_prefix`（默认 `<固定镜头，无运镜>`，写成空字符串就不加；这一行由脚本加，不参与动作的检查）、`include_scene`（默认 `false`，要放画面描述时写 `true` 并填 `scene`）、`include_line`（默认 `false`）。
- `hands`、`posture`：各一句短话，照图写；手里拿着东西的写明拿着什么。
- `motions[i]`：第 i 段的叙述。

## 六、校验和效果

`build_prompts.py` 对中文叙述的检查：

- **会拦的**：夹了英文、写了时间点或秒数、用了引号、写了嘴和表情、用了比喻、写了镜头运动或前后方向的动作、写了具体手指数、碰脸、开头或结尾没提 `<Picture 1>`、超长；没填或填错 `image_type`；`lines` 和识别文字对不上。
- **只提示的**：双手交叉、叠放、往中间靠拢；手抬得过高；叙述太长或太短。

提示不拦截：看到提示判断一下，该改的改。

成片里的动作不会和写的一模一样。只有画面明显出错（多手、多出东西、镜头被拉远、手形错乱）才值得改写法重跑；手偶尔停一下、某个动作没做出来都可以接受。

## 七、要图片时顺带看一眼

图片类型没有好坏，但有两件事直接影响成片，拿到图就看：

- **起始姿态越中性，接缝越干净**：嘴闭着、表情平静、头正、手自然放着。嘴张开或手抬在半空的图能用，按“非中性”处理并告诉用户。
- **手要有地方落**：画面里看得见桌面，或留出了腰部以下的一点空间，起落和拍、点这类动作才做得出来；头顶和两侧留一点空，身体才有地方动。

遇到受限的图，告诉用户一句这张图的限制和更合适的图是什么样，由用户决定，不替他拒绝。
