# RunningHub 接口与验证状态

记录日期：2026-10-03。"已验证"指用真实 Key 在本机实测过。

## 接口（已验证）

| 用途 | 调用 |
|---|---|
| 上传 | `POST https://www.runninghub.cn/openapi/v2/media/upload/binary`（multipart，字段 `file`）→ 返回 `data.fileName`，**把它原样当作 `fieldValue`** |
| 提交 AI 应用 | `POST /openapi/v2/run/ai-app/{appId}`，请求体 `nodeInfoList` + `instanceType` + `usePersonalQueue:"false"` |
| 查询 | `POST /openapi/v2/query`，`{"taskId": ...}` → `status`（RUNNING / SUCCESS / FAILED）、`results[]`（`outputType`、`url`）、`usage`（`consumeMoney`、`taskCostTime`） |

鉴权：`Authorization: Bearer <API Key>`。结果链接约 24 小时有效，要马上下载。**失败的任务不计费**（`consumeMoney` 为空）。

## 应用的输入

应用接收本段音频、人物图片、提示词和宽高（宽高必须是 32 的倍数，范围 256–2144）。各输入对应的编号写在 `scripts/avatar/common.py` 里，由 `run_avatar.py` 填写，不需要手动处理。

| 输入 | 节点 | 字段 |
|---|---|---|
| 音频 | 348 | `audio` |
| 人物图片 | 114 | `image` |
| 提示词 | 9008 | `string` |
| 宽、高 | 139、140 | `value` |
| 随机种子 | 131 | `noise_seed` |

随机种子是 2026-10-13 工作流新增的输入（用户提供的调用示例）。`run_avatar.py` 默认传 42，`--seed random` 或 `--seed <整数>` 可以换。换种子确实会改变结果（同一段换种子后，同一时刻的画面差平均 11–37，完全相同时为 0）。**没验证的**：不传这个节点时工作流用什么种子。

实例：`default`（24G）/ `plus`（48G）/ `ultra`（84G）。本技能默认 `plus`，用户授权过；`ultra` 没有授权，不自行使用。

## 应用从哪来

`DEFAULT_APP_ID`（在 `scripts/avatar/common.py`）是创建者在 RunningHub 上发布的 AI 应用，使用者用自己的 API Key 调用它，费用算在使用者自己的账号上。

**已验证**：换用另一个账号的 Key（2026-10-06）后，同一个应用 21 段全部跑通，并发 3 路没有被拒；说明别的账号的 Key 可以直接调用它。如果以后被拒绝，把原始报错告诉用户；需要换用别的应用时用 `python scripts/avatar/check_setup.py --set-app-id <应用ID>` 记录。

**费用**：换到新账号后，接口返回里没有费用字段（`run_avatar.py` 里显示“费用=None”、合计 0.0 并不是没花钱），费用要在 RunningHub 后台查。下面的耗时和单价是旧模型的数据，云端应用换了模型之后没有重新测。

## 效果方面的实测记录

- 每个节拍都写两只手、不让任何一只手静止：近似静止的帧占比从 37%/41% 降到 25%/19%。
- 两条片子里各出现过一段"说话时嘴闭着或几乎不动"（约 10 秒），音频本身没有异常；这个问题现在由云端应用处理，成片仍要看嘴部逐秒图确认。
- 第二条片子（55.4 秒，5 段）：5 段全部一次成功，合计 2.931 元（约 0.053 元/秒）；四个接缝切点前后的画面差 1.0–1.9，与段内相邻帧差的中位数 1.59 相当。
- 出现过提示词里没有写的手形（双手握拳），属于模型自行发挥，需要人看。
- 逐秒色彩检测的标定（2026-10-04，一个人物、四个版本）：正常的秒，背景色相相对图片偏转 ≤12°、彩度是图片的 0.9–1.7 倍；整幅变青或变黄绿的秒色相偏转 26–134°；褪成灰白的秒彩度 ≤0.4 倍。阈值取 20° 和 0.55。另一个人物（背景本身是紫红色）全片色相偏转 5–7°、彩度 1.1 倍，没有误报。背景里局部多出东西（架子上多出亮屏）这种检测不到。
- 通用要求改由云端应用加入、技能只发送画面描述、双手、台词和动作编排之后（2026-10-03）：同一条 55.4 秒的片子 5 段全部一次成功，合计 2.95 元；每段说话时嘴动量 6.25–7.26，没有出现嘴不动的段；左右手静止帧 16% / 11%；各段色差 ≤0.8；接缝连续。只跑了这一条。

## 画面问题的实测结论（2026-10）

- **镜头被推近／拉远**和动作写法关系不大，和“这一段的音频 + 种子 + 工作流版本”关系更大：换了几种写法，被拉远的总是同样几段；只换种子重跑，有时好、有时更差。提示词第一行加 `<固定镜头，无运镜>`、不放画面描述之后没有再出现（验证过一轮）。
- **工作流版本会改变结果**：同样的提示词和种子，换一版工作流，结果可能从完全正常变成多段被拉远。排查画面问题时先问工作流有没有改过；每段生成时的工作流版本记在 `result.json` 和历史版本里。
- **段长**：16–17 秒的段后半更容易走样、出多手；每段 12 秒以内明显好转。官方 H3 文档给的单条时长是 4–15 秒。
- **多手**几乎都出在双手交叉、叠放、往中间靠拢、举过肩、一只手在一句里去好几个位置的那一拍上。
- **手里多出东西**对应过“大幅摊开”“身体轻轻一带”这类写法；“带”换成“侧倾”后消失。
- **烧字幕**：提示词里放台词原文时出现过整段烧上台词；不放台词后没再出现。
- 接口一直不返回费用，按旧参考价估算，以后台为准。

## 没验证的

- **分段上限**：现在是 14 秒（2026-10-14 用户定；之前是 12 秒）。13–17 秒的段在 768P、plus 实例上都能一次跑成功（30 多段），但段越长后半越容易走样；失败只会报告，不会自动换 `ultra`。
- **超出并发数时接口返回什么**：没测过，`run_avatar.py` 按关键词（并发/排队/限流）和 HTTP 429 判断后等待重试，是推测。
- **重试与续跑逻辑**：只用模拟的云端测过（`tests/avatar/test_retry.py`，10 种情况），没有在真实云端触发过各类失败；"余额不足"等不可重试的判断也是按关键词推测，真实错误文案可能不同。
- **非 16:9 画幅**：9:16（768×1376）已在云端跑通多条；1:1、4:3、3:4、21:9 的尺寸是按同一个公式算的，没有实际跑过。

- **获取 Key 的引导文案**（`scripts/avatar/common.py` 的 `GUIDE_KEY`）：专属邀请链接注册可额外获得 1000 RH 币；注册后登录，上方选“API”→ API 页面左上“获取密钥”→ 密钥页面新建密钥并复制。这是维护者给的路径，页面改版后以用户看到的为准。
